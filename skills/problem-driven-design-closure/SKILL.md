# 问题驱动设计闭合

本技能也称“四步法”或“4步法”。

## 目标

在缺少现成概念框架时，从不可回避的真实问题出发，发现系统必须具备的最小逻辑与结构。

核心循环：

```text
问题 → 逻辑 → 精简 → 闭合
  ↑                       │
  └──── 新缺口形成新问题 ─┘
```

不要先发明对象、字段或流程再寻找用途。新增任何结构前，必须证明删除它会造成具体断口，而且该断口无法由既有权威源机械、唯一地弥补。

## 工作流

### 1. 问题

把模糊担忧改写为一个刚性问题：如果不解决，哪个可观察行为一定无法正确完成？

- 说明当前场景、目标和失败表现。
- 区分真实断口与审美偏好、未来猜测或实现便利。
- 一次只追踪一条主因果链；新缺口成为下一轮问题。

### 2. 逻辑

从正确决策反向追踪：

```text
需要什么事实？
→ 事实在哪里产生？
→ 如何验证？
→ 如何获得业务语义？
→ 如何传递和消费？
→ 谁负责语义判断？
→ 谁负责机械校验？
→ 谁允许看到或修改？
```

标出每个事实的唯一权威来源、派生投影、生命周期和失败出口。隐藏前提必须显式化；无法说明来源的字段不得作为正式事实。

### 3. 精简

按顺序删除需求、结构和流程，再考虑优化与自动化：

- 能从权威源机械且唯一推导的字段、状态、事件或接口定义，不得成为第二真相源。
- 只改名或转发的包装、为形式对称增加的镜像结构、为修补前序复杂度存在的步骤应删除。
- 缓存或投影可以保留，但必须标记为易失、可重建，且不能反向覆盖权威源。
- AI 负责开放语义判断；确定性系统负责权限、类型、引用、唯一性、覆盖和状态转换校验。

每个保留项都要回答：删除后会失去哪项不可替代的语义、身份、验证、安全或审计能力？

### 4. 闭合

验证剩余模型能够完整运行：

- 正常路径：输入、决策、执行、观察、验收和下一步是否连通。
- 失败路径：缺失、冲突、超时、取消、无权限和无法归因时是否确定停止。
- 唯一性：同一语义是否只有一个权威源；重复来源是否机械拒绝。
- 生命周期：临时事实何时产生、生效、固化和释放。
- 边界：AI、机械执行器、持久化知识和公开出口是否越权或串层。
- 演进：候选、验证和发布是否会污染当前正式状态。

若发现新断口，把它改写为下一轮刚性问题；不要用兜底字段或额外状态掩盖。

## 输出格式

按实际复杂度给出以下内容，避免为了格式制造空章节：

```text
刚性问题
必要事实与权威来源
完整因果链
责任和信任边界
删除项与保留理由
最小数据结构 / 流程
失败、冲突与生命周期门禁
闭合结论
新暴露的问题（如有）
```

复杂关系优先用小型 ASCII 流程图。区分已经证明的结论、仍需证据的假设和仅供选择的方案。

## 停止条件

满足以下条件时停止继续加结构：

- 刚性问题已有确定答案；
- 正常和失败路径均可执行；
- 每项持久化事实只有一个权威来源；
- 派生数据均可重建；
- 删除任一剩余结构都会造成可说明的真实断口；
- 没有未处理的新问题。
