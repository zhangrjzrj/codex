# legion-dev（军团化开发）

## 统一口径（名称）
- 本技能唯一标准名：`legion-dev`（目录名与 `name:` 保持一致）
- 全局范围（`$CODEX_HOME/skills`）内 `name:` 必须唯一，禁止不同技能包复用同一个 `name:`

## 铁律（最高优先级）
只有足够小的步伐，才能确保稳定坚实、质量可靠；同时把上下文压到足够小，才能确保准确性与质量。

## 目的
把“多 AI 协作 + 门禁”变成固定流程：先对齐验收与停止条件，再开始执行；执行中按证据门禁推进，避免 AI 在关键前置步骤翻车后继续扩大损失。

## 适用场景（触发条件）
- 存在明确验收点/前置门禁的任务
- 会改分支指针（rebase/reset/cherry-pick）或大规模变更
- 需要“baseline 语义不变”的变更（必须有证据代理：测试/快照/契约/指标）
- 多人/多 agent 并行开发需要拆解与汇总

## 硬触发表（强制进入军团流程）
只要用户意图命中任一条，就必须先输出执行卡并等人确认（未确认前，不执行高风险命令）：
- 改指针类：`rebase` / `reset` / `cherry-pick` / “对齐到某个 commit” / “回退一串提交”
- 高风险批量变更：大范围重构/清理/替换、跨模块联动修改
- 强验收诉求：“闭环做到通过” / “门禁” / “执行卡” / “baseline 语义不变”

## 强制流程（必须遵守）
1) 先输出“执行卡”（Execution Card），不允许直接动手改代码/跑高风险命令  
2) 等人确认执行卡（目标/边界/门禁/例外）  
3) 按步骤执行：每一步都产出门禁证据（PASS/FAIL 二值）  
4) 任一步 FAIL：立即停止，不进入下一步；需要例外必须更新执行卡并重新确认  
5) 过程与结论必须落盘到项目内 `.codex-memory/`（主线与业务子线分流）

## 角色分工（4+1，降低上下文长度）
必备 4 角色：
- 编排者（Orchestrator）：产出执行卡；切分任务；收敛门禁；汇总证据；做主题分流。
- 开发者（Developer）：只负责实现“单步任务”，输出变更摘要；不做放行裁决。
- 测试者（Tester）：只负责产出门禁证据与 PASS/FAIL；不做需求解释。
- 审阅者（Reviewer）：只基于“变更摘要 + 门禁证据”做放行/驳回，关注边界与风险。

可选 +1（早期可并入编排者）：
- 记录员（Scribe）：把每步结论/证据摘要写入 `.codex-memory/`，确保可恢复与可审计。

## 最小证据包（每步交接工件）
每一步都必须产出以下最小包，避免把整段对话塞给下一个角色：
- Step 目标：1 句
- 变更边界：2–5 条
- 本步改动摘要：3–8 条（含关键文件路径）
- 验收标准（本步门禁）：必须可判定的 PASS/FAIL（证据是什么、阈值是什么）
- 门禁证据：关键行（命令输出/测试结论/快照对比/指标数值）
- 裁决：PASS/FAIL + 下一步入口/失败处理

## 小步闭环协议（强约束）
每一步都必须带明确验收标准（门禁），小步闭环推进：

```text
Orchestrator（执行卡/验收标准/派单）
-> Developer（单步实现 + 变更摘要）
-> Tester（按验收标准产出证据 PASS/FAIL）
-> Reviewer（基于摘要+证据 放行/驳回）
-> Orchestrator（更新计划/标准/例外，进入下一步或结束）
```

规则：
- 没有验收标准就不开始执行（先补齐执行卡与门禁）。
- 未通过当前步验收标准，不得进入下一步（FAIL 必须回到本步或重写方案）。
- 验收标准必须二值化：PASS/FAIL，并落到证据层（测试/快照/对比/指标阈值/输出断言）。

## 执行卡（必须包含）
- 目标（Goal）：一句话
- 变更边界（Boundary）：允许改/禁止改
- 步骤（Steps）：3–7 步，每步只做一件事
- 每步门禁（Gates）：证据 / 通过条件 / 失败处理
- 风险点（Risks）：3 个最可能翻车点 + 预防
- 例外（Exceptions）：允许变化 + 谁批准

## 证据包（目录契约）
默认证据包落在当前项目工作目录（不是全局目录）：
- `.codex-memory/artifacts/legion/YYYYMMDD-HHMMSS-<topic>/`
必选文件（最小契约）：
- `execution_card.md`（确认后的执行卡）
- `steps/step-01.md` …（每步 PASS/FAIL + 关键证据摘要）
- `result.md`（最终结论/未完成项/下一步）

- 本技能只记录“协同协议/门禁/流程决策”到主 thread。
- 业务细节（例如渲染/水/深度等）必须分流到独立 thread 文件。
