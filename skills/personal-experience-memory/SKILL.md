# 个人经验记忆

## 定位

这是一个事实优先的项目级经验记忆层。它在开发过程发现已确认的坑点、边界条件、失败根因或高价值取舍时，低成本自动把事实、证据和人类判断整理为正向或反向经验，写入当前工作区的 `.j-memory/`；后续任务开始或出现相关失败/边界信号时，按问题域和语义信号自动联想检索。

经验正文只归当前项目所有；总控目录可以保存跨项目导航索引，但不得保存另一份完整正文。它类似记忆系统的自动沉淀层，不要求用户为每个经验显式发起保存操作。

它不是：

- 代码事实的替代来源；
- 自动形成设计理念的系统；
- 只凭对话回忆生成事实的摘要器；
- 自动修改业务代码、发布产物或扩大权限的执行器。

## 触发方式

- 用户说“结合经验分析：<问题>”时：先检索当前工作区 `.j-memory/index.md` 和相关 `threads/*.md`，同时返回相关正向和反向经验。
- 用户说“保存相关经验”时：立即从当前可见事实和证据生成经验记录。
- 任务结束、Bug 修复、测试闭环、用户纠正判断或确认重要边界时：自动判断是否存在值得复用的经验，有则沉淀，无则不写或记录 `No material change`。
- 每个新任务开始、进入已知问题域或出现相似错误/现象时：自动读取当前项目 `.j-memory/index.md`，按问题域、语义标签、recall signals、平台、版本和资源上下文联想候选经验；命中后再读取相关线程。
- 没有受控事件采集器时，不声称知道未进入当前上下文的命令、文件变化或环境细节。

## 事实与结论边界

1. 事实必须来自工具输出、文件、Git、测试报告、日志、截图或用户明确陈述；不要用模型记忆补全未记录的细节。
2. 解释、根因和可复用规则必须标记为结论或候选，不得伪装成事实。
3. 每条经验至少包含：问题/目标、方向、上下文、事实、证据、结论、适用条件、排除条件和状态。
4. 不确定、冲突、过期或未归因变化必须显式标记 `unknown`、`unverified`、`conflicted` 或 `stale`。
5. 一次成功不能自动升级为稳定规则；稳定经验需要重复验证或用户明确确认。

## 自动沉淀门槛

经验的价值通常低于代码和 Spec，因此默认采用“低成本、低噪声”策略：

- 真实 Bug 已确认根因；
- 失败路径具有可复用的证据和边界；
- 用户纠正了模型判断；
- 发现跨版本、平台、配置或资源的隐藏约束；
- 做出了代码或 Spec 无法表达的方案取舍。

以下内容默认不保存：普通代码解释、一次性命令过程、无证据猜测、已经完整写入 Spec 的规则、只对当前局部实现有意义的细节和没有复用价值的偶然成功。

自动沉淀不是自动执行修复，也不是把候选经验强行升级为规则。无法确认复用价值时，优先不写；必须保留时写成 `candidate` 或 `unverified`，并记录下一步验证。

## 正向与反向经验

- `positive`：在明确上下文和前提下，哪种做法有效，以及如何验证。
- `negative`：在明确上下文和前提下，哪种做法失败、无效或不应继续，以及失败证据是什么。
- 反向经验不是无条件禁令；必须保留失败发生的上下文和未验证范围。

## 最小沉淀流程

```text
检索相关历史
  -> 读取当前任务事实与证据
  -> 区分事实、观察、假设和结论
  -> 生成正向或反向经验记录
  -> 标注适用边界、反例和证据引用
  -> 写入项目 .j-memory
  -> 更新 index.md
```

推荐的经验记录内容：

```text
方向：positive / negative
问题域：构建 / 缓存 / 渲染 / 资源 / 时序 / 发布 / 其他
语义标签：同义表达、错误词、任务词
联想信号：可触发回想的现象、日志片段或上下文
目标/问题：
上下文：版本、平台、配置、资源和环境
已确认事实：
支持证据：
结论/可复用做法：
适用条件：
 排除条件/反例：
状态：candidate / verified / stale / conflicted / unverified
下一步验证：
```

## 写入规则

- 只写当前工作区相关的 `.j-memory/index.md` 和主题线程；不要新建平行记忆目录。
- `.j-memory/` 是项目经验正文的唯一权威来源；总控目录只允许保存项目路径、主题、文件引用和状态等导航信息。
- 保留原始证据路径和 hash；摘要不能替代原始证据。
- 更新索引时只增加主题摘要和线程引用，不把完整过程复制到索引。
- 不执行 `git add`、暂存区操作或提交，除非用户明确要求。
- 不把凭据、密钥或不应持久化的敏感内容写入经验文件。
- 经验记录应简短、可执行；没有实质变化时记录 `No material change`。

## 检索输出

自动联想和用户显式检索使用同一套输出规则。联想只产生候选提示，不替代当前代码和证据分析：

返回历史经验时说明：

- 命中的正向经验和反向经验；
- 为什么命中以及当前上下文是否匹配；
- 结论的证据强度和状态；
- 已知反例或过期风险；
- 建议的最小验证动作。

不要默认输出全量历史、全量拓扑或未经筛选的相似文本。
